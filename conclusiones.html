Conclusiones y Trade-offs

Decisiones arquitectónicas adoptadas, tecnologías seleccionadas y desafíos identificados durante el diseño de MediConnect.

Trade-offs Arquitectónicos

Decisiones clave y sus implicaciones.

Arquitectura Hexágona (Ports & Adapters)

Separación clara entre dominio, aplicación e interfaces. Faculta testing independiente y cambios de tecnología sin afectar el núcleo.

  • Testing unitario sin base de datos.
  • Cambio de proveedor de pagos sin tocar dominio.
  • Principio de inversión de dependencias cumplido.

Microservicios vs Monolito

Elegimos microservicios por escalabilidad independiente por dominio (citas vs pagos vs historial).

  • Deploy independiente: menor riesgo de regresión.
  • Complejidad de red y consistencia eventual aceptada.
  • Requiere observabilidad fuerte (logs, trazas).

Consistencia Eventual vs ACID

Historial clínico tolera lag de segundos (eventos). Casos críticos (pagos, recetas) usan transacciones ACID.

  • Eventos de dominio sincronizan duplicados.
  • Riesgo: datos inconsistentes temporalmente.

Duplicación vs Normalización

Datos duplicados en cada microservicio para aislar dominios, evitando locks globales.

  • Aísla fallas de un servicio.
  • Aumenta complejidad de sincronización.

Tecnologías Seleccionadas

Stack tecnológico para cada capa del sistema.

Backend & API

  • Node.js 18 + Express — Alto rendimiento, ecosistema
  • TypeScript — Type safety, mantenibilidad
  • Docker — Contenedores, consistencia ambiente
  • RESTful APIs — Estándar abierto, fácil debugging

Base de Datos

  • PostgreSQL 15 — ACID, JSON support
  • Redis 7 — Cache, sessions, rate limiting
  • AWS RDS — Manado, backups automáticos
  • S3/MinIO — Archivos médicos, recetas

Infraestructura

  • AWS/GCP — Elasticity, global
  • Docker + ECS — Deploy sin servidor
  • NGINX + ALB — Load balancing, SSL
  • CloudFront — CDN, baja latencia

Seguridad y Cumplimiento

Cumplimiento de RNF2 y normativas sanitarias.

Cumplimos con RNF2 (TLS 1.3, AES-256) y normativas sanitarias (HIPAA/LOPDGDD).

En Tránsito:

  • • TLS 1.3 con Perfect Forward Secrecy
  • • Certificados Let's Encrypt automáticos
  • • HSTS headers, CSP policies

En Reposo:

  • • AES-256 para datos sensibles
  • • RDS encryption at rest
  • • S3 SSE-S3 para archivos

Desafíos Identificados

Desafíos encontrados durante el diseño.

Seguridad Médica

La encriptación AES-256 es obligatoria. No se puede sacrificar por performance.

Telemedicina

WebRTC es complejo. Se requieren STUN/TURN servers para conectividad.

Regulación

Ley de Protección de Datos médicos (HIPAA/LOPDGDD) exige auditorías periódicas.
